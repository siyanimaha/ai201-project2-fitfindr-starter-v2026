# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
before any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe.

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**

I chose 4 out of 5 because the search uses keyword matching, so some ways of
wording a query may not match the listing data even when a similar item exists.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**

I chose 5 out of 5 because this path does not depend on finding a good match.
If the search returns nothing, the program should always stop before calling
the next tool.

---

## 3. The selected item stays the same between tools

Given a matching query, the ID in `session["selected_item"]` matches the ID of
the item passed to `suggest_outfit` in 5 out of 5 tries.

**Why this target:**

I chose 5 out of 5 because the selected item is passed directly through the
session, so the item should stay the same when it moves to the next tool.

---

## 4. The fit card includes important listing information

For a successful search, the fit card mentions the selected item's price and
platform in at least 4 out of 5 tries.

**Why this target:**

I chose 4 out of 5 because the fit card is generated by a model, so the wording
can change between runs. However, it should still include important information
about the listing most of the time.

---

## 5. Search results respect the maximum price

When a maximum price is provided, every listing returned by `search_listings`
has a price less than or equal to the requested maximum price in 5 out of 5
tries.

**Why this target:**

I chose 5 out of 5 because the price filter is handled directly by the search
tool and does not depend on the model. The search should never return an item
that is over the user's maximum price.
